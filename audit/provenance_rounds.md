# Provenance rounds (issue #1)

source and round, in the order they were run (the template of issue #1,
section 4). Read by no code; the machine-readable state is in
`sources/databases/<Src>/primary_references.csv`, `Bib/pending_citations.csv`,
`Bib/scite_checks.csv` and `reports/warnings_citations.md`.

## 2026-10-04 -- Herberstein_etal_2022 (pilot A0, Stage 1 of issue #1; hop 2)

Tooling `tbmcite 0.1.0` (branch `issue-1-pilot-herberstein`, merged with main f1eee70 after the Hebert pilot).

- Parser: `BodyMass_Herberstein_etal_2022.r` keeps the hash key `h:<sha1-8>` of the normalised `fullReference` as `ref_keys` (`ParseInRowCitations()`; 2,856 records, 0 NA, 193 keys; one in-text form, "Terblanche, Klok, & Chown, 2004", stands for two papers, which is why the full text and not the in-text form is hashed). - Hop 2 (issue #1, 1.3) implemented in `BuildProvenance()`: a resolved reference whose CiteID, bib key or DOI is a registered source label is an intermediate compilation (`MatchIntermediateLabel()`); the intermediate's own resolved references for the species give `compiled_via_compilation` rows at hop 2 with `via_cite_id` (`IntermediateReferences()`), a `self` reference of the intermediate gives `compiled_from` citing it, and otherwise the intermediate is the terminal citation (`compilation_terminal`, owner decision). First case: Chown et al. 2007 (244 records, 8 ant species, Chown's own Appendix S1 measurements) -> 7 accepted species `compilation_terminal` at `Chown_etal_2007` until Chown is ingested. `Chown:2007aa` received `doi` and `volume` in the curated bib and the source `Citation.bib` (owner-accepted hand edit) so that the DOI route and the key reuse of `--bib` recognise it.

OpenAlex now limits keyless use to 1,000 requests a day and answers the rest with 429 and a day-long Retry-After, for which httr2 slept ("Waiting 83003s for retry backoff"): `CachedGET()` treats such a 429 as an exhausted quota (classed condition `citations_quota`, host flagged for the session), `VerifyPrimaryReferences()` leaves the affected references unverified and reports them, `OPENALEX_API_KEY` is sent when set (never stored: the cache key and the stored URL drop it).
