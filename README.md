# TaxonBodyMass_DB

A compiled, harmonized database of species body masses (in grams) drawn from many published sources spanning the full diversity of heterotrophic life — from microbes to large vertebrates. Developed in support of [FracFeed_DB](https://github.com/marknovak/FracFeed_DB) and [TaxonBodyMassML](https://github.com/TaxonBodyMassML/TaxonBodyMassML).

## Data Sources

Body mass data are compiled from primary sources and databases covering organisms across all major taxonomic groups, including bacteria, protists, marine zooplankton and invertebrates, spiders, fish, amphibians, reptiles, birds, and mammals (modern and fossil). Sources include both ecological databases (food-web, metabolic-scaling, predator-prey, movement) and taxonomic trait databases (life-history, body size). Live downloads from [FishBase](https://www.fishbase.org) and [SeaLifeBase](https://www.sealifebase.ca) are supported via the `rfishbase` package.

Bibliographic information for all sources is in `Bib/TaxonBodyMass_Citations.bib`.

## Pipeline

The pipeline is written in R. The main entry point is `R/RunMe.r`, which orchestrates all steps:

1. **Per-source parsing** — each source has its own script at `sources/databases/<SourceName>/BodyMass_<SourceName>.r` that reads raw data files, extracts taxon names and body masses, converts units to grams, and saves a cached `.Rdata` file to `sources/Rdata/`. Sources that report dry, ash-free dry or carbon mass are converted to wet grams with the group-specific factors in `R/library/mass_conversion.r` (`ToWetMass()`); each such script's `README.md` states the mass type reported by the source and the conversion group applied, and the CiteIDs of the conversion references are appended to the record's `source_mass` label (e.g. `Kendall_etal_2019; Studier_1992`) so they are cited alongside the source. Rows that the source itself flags as imputed, genus-averaged or taken from another species are removed in the parse scripts (`DropImputed()` in `R/library/helpers.r`) and logged to `audit/imputed_rows.csv`; each source's `README.md` records this in an `Imputed rows:` line, which `R/library/check_source_docs.r` checks at every run. These cached files are git-ignored and regenerated by setting `recompile = TRUE` in `RunMe.r`.

2. **Taxon name cleaning** — applied uniformly to every source before merging:
   - `R/library/fix_formatting.r` — normalizes encoding, whitespace, capitalization, and truncates subspecific epithets to binomials
   - `R/library/fix_misspellings.r` — corrects known misspellings
   - `R/library/fix_nontaxa.r` — removes placeholder identifiers, functional-group labels, and other non-taxon entries
   - `R/library/filter_extinct.r` — removes extinct species (list in `audit/extinct_taxa.csv`, compiled by `sources/extinct_taxa/build_extinct_taxa.r` from the status columns of MOM v10.2, PHYLACINE 1.2 and AVONET); the MOM and PHYLACINE scripts also drop their own extinct rows
   - `R/library/check_taxon_names.r` — stops the run if any cleaned name is not a single token (`Genus_species` or `Genus`), which a replacement value typed with a space would produce; `RunMe.r` tells species-level from genus-level records by the underscore when it merges the sources, so such a name would be filed as a genus (issue #28). Exercised without network access by `Rscript R/library/tests/test_taxon_name_guard.R`

3. **Google Sheet override** — lab-curated values (`BM_data` tab) replace all compiled records for the same taxon.

4. **Taxonomy enrichment and autotroph removal** — every unique name is resolved once to an accepted species and its full kingdom-to-species classification through GBIF, NCBI, WoRMS, Catalogue of Life (ChecklistBank), ITIS and Wikidata in turn, with a final GBIF backfill of missing higher ranks (`R/library/enrich_taxonomy.r`; details in `sources/passes/enrichment_pipeline.md`). Results are cached in `sources/enrich_cache.Rdata` so re-runs only query new names. Manual corrections live in `R/library/fix_taxonomy_ranks.r`. `R/library/filter_autotrophs.r` then removes autotrophs: the kingdoms Plantae, Viridiplantae and Fungi; predominantly photosynthetic phyla (Ochrophyta, Bacillariophyta, Haptophyta, Cryptophyta, Chlorophyta, Rhodophyta, Charophyta, Glaucophyta, Streptophyta, Euglenophyta, Cyanobacteria, Cyanobacteriota); and a curated list of photosynthetic or mixotrophic dinoflagellate and euglenid genera. Heterotrophic protists (ciliates, foraminifera, apicomplexans, kinetoplastids, amoebae, heterotrophic dinoflagellates and euglenids) are retained.

5. **Merging, de-duplication and range filter** — within each source, body masses are summarised as the geometric mean across records resolving to the same accepted species. Records are grouped by the source *label* (the first token of `source_mass`; the conversion CiteIDs appended after `;` do not split a source), and the six VertNet dumps are pooled as one source because the `traits` dump re-exports specimens of the class dumps (every dump label stays in `source_mass`).

   The same datum often reaches the database through several compilations (AVONET and EltonTraits both reproduce Dunning's CRC Handbook; COMBINE reproduces Amniote, PHYLACINE and MOM; Hoehler et al. 2023 reproduces Makarieva et al. 2008, which reproduces Chown et al. 2007; Meiri 2018 applies the Feldman et al. 2016 equations to the same lengths, and so on). Averaging such copies as independent estimates inflates `n` and biases the cross-source mean, so `R/library/dedupe_sources.r` collapses them before Pass 2 (issue #5). Two layers combine: the hand-maintained dependency registry `Bib/source_dependencies.csv` (one row per edge `child_label -> parent_label`, see below) collapses a child value into its parent, or into a sibling that shares a parent outside the database, only when the two values also agree within the edge's tolerance (`tol_log10`: 1e-6 for verbatim copies, 0.0105 where the child re-rounded or re-derived the value); edges are transitive, and `provenance_only` edges document a relation whose values generally differ: they grant no tolerance-based (registry) collapse. A blind rule then collapses values that are the same number to at least three significant digits in any two sources of a species, whatever the registry says about the pair (identical values are the same datum; on a `provenance_only` pair such a collapse is labelled `blind (provenance_only edge)` in the summary report); values of one or two significant digits, round numbers such as 20 or 1500 g, are left alone as ambiguous. Matching values form a component per species; the registry ancestor (or the lowest-`priority` sibling) is kept and the others are recorded in `source_dependencies` as `dropped<kept`. `reports/dedupe_summary.md` lists every edge with the species it shares and collapsed, the species left with a single independent value, and the residual identical pairs the registry does not explain (candidates for new edges or shared primary literature).

   Across sources, the independent values are combined as the arithmetic mean (owner decision 2026-10-03, issue #16): the arithmetic mean is the published convention of the database, so outputs stay comparable with earlier releases and with the manuscript; within-source skew is already handled by the geometric mean of the first pass, and the cross-source step combines per-source central values, where the choice matters less once duplicated values are collapsed; switching to the geometric mean would have moved 795 species by more than 0.1 log10, always downward, a larger and systematic shift than de-duplication, and would entangle two effects that should stay separable; neither choice affects `log10_range` or the range filter. `log10_range` records the spread of the independent values, `source_mass` lists every contributing source, `n` counts every record, and `n_sources`, `n_independent` and `source_dependencies` record the de-duplication. `R/library/check_enriched.r` writes QC reports to `reports/` (`warnings_taxonomy.md`, `warnings_mass_values.md`, `warnings_name_change.md`), and species whose independent values disagree by more than one order of magnitude (`log10_range > 1`) are removed (`R/library/remove_high_range.r`). Counts from this step (including `nValuesCollapsed`, `nSpeciesSingleDatum` and `nDependencyEdges`) are written to `../TaxonBodyMassML/ms/numbers_db.tex` for the manuscript.

6. **Genus-level aggregation** — species-level masses are averaged by their resolved (accepted) genus to produce a supplementary genus-level output; synonymous or misspelt input genera therefore fold into the accepted name. Genus-only input records, which bypass enrichment, contribute under their raw genus name, each as one independent value.

### Source dependency registry

`Bib/source_dependencies.csv` records which sources copy or derive their body masses from which others. Columns: `child_label` (a `source_mass` label), `parent_label` (a label, or the name of a compilation outside the database such as `Dunning_2008`, `White_2006`, `Nagy_1999`, `CareyJudge_2000`), `parent_in_db` (TRUE/FALSE), `relation` (`copies`, `via` an intermediate compilation, `shared_primary`, `derived_same_input`, or `provenance_only`), `tol_log10` (the largest |log10 difference| at which a child value counts as the parent's), `priority` (which of several siblings of an external parent is kept: the lowest number; one value per label), `status` (`confirmed` by the source's own documentation or `suspected` from the values alone), `n_rows_child` (records the child attributes to the parent where it does so per row), `evidence` and `added`. Where several routes connect two labels the loosest tolerance applies. `LoadSourceDependencies()` stops the pipeline when a child or an in-database parent is not a label of any source frame, when an external parent is one, on a cycle, or on conflicting priorities, so a renamed or removed source has to be reflected in the registry. Add an edge when a source's documentation or a high fraction of identical values (see the residual table of `reports/dedupe_summary.md`) shows that it reproduces another; use `provenance_only` when the values differ (the pair then gets no tolerance, but values identical to three significant digits are still collapsed by the blind rule and counted per edge in the report). The helper is tested without network access by

```bash
Rscript R/library/tests/test_dedupe_sources.R
```

and `Rscript R/library/dedupe_audit.r [--before <earlier TaxonBodyMass.csv>]` replicates Pass 1, the de-duplication and Pass 2 from `sources/Rdata` and checks the released CSV against it (invariants, agreement, per-edge fractions, the shifts the de-duplication causes).

## Outputs

| File | Description |
|---|---|
| `TaxonBodyMass.csv` | One row per accepted species. Columns: `genus`, `species`, `taxon` (a representative input name), `taxon_provided` (all input names, `;`-separated), `log10_range` (spread of the independent per-source values), `mass_g` (grams, arithmetic mean of the independent values), `source_mass` (`;`-separated labels of every contributing source and conversion reference), `n` (records in all sources), `n_sources` (per-source values, the VertNet dumps counted once), `n_independent` (values entering the mean), `source_dependencies` (values collapsed as copies, `dropped<kept` pairs `;`-separated, empty when none; pooled VertNet dumps appear joined by `+`), `kingdom`, `phylum`, `class`, `order`, `family`, `taxonomy_source`, `gbif_confidence`, `gbif_status`, `gbif_family`, `gbif_order`, `species_changed` |
| `TaxonBodyMass_GenusLevel.csv` | Arithmetic mean body masses by accepted genus (`-`-separated source labels), with `n` (records) and `n_independent` (independent values summed over the genus's species and genus-only records) |
| `Bib/source_dependencies.csv` | The source dependency registry used for de-duplication (see pipeline step 5) |
| `reports/dedupe_summary.md` | Per-edge and residual summary of the de-duplication, regenerated at every run |
| `audit/imputed_rows.csv` | Log of the rows the parse scripts dropped as imputed, one row per `DropImputed()` call (`source`, `reason`, `n_dropped`, `n_taxa`, `n_kept`); rewritten by `RunMe.r` at every run with `recompile = TRUE`. The `Brose_2005` row is written by `R/library/data_retrieve.r`, so only a run with `DataRetrieve = TRUE` regenerates it (see `audit/README.md`) |
| `audit/extinct_taxa.csv` | The extinct-taxa list applied by `RemoveExtinct()` (pipeline step 2), rebuilt by hand with `sources/extinct_taxa/build_extinct_taxa.r` from the MOM, PHYLACINE and AVONET status columns |
| `Bib/TaxonBodyMass_CitationCiteIDs.csv` | Maps BibTeX keys to `source_mass` labels for citation tracing |
| `Bib/TaxonBodyMass_Citations.bib` | Full BibTeX bibliography for all sources |

## Usage

### Prerequisites

Install the required R packages:

```r
install.packages(c("plyr", "dplyr", "googlesheets4", "stringr", "readxl"))
install.packages("rfishbase")
install.packages("rdataretriever")
```

The `rdataretriever` package requires Python and the [`retriever`](https://retriever.readthedocs.io) Python package. It is used only when `DataRetrieve = TRUE` in `RunMe.r`. `RunMe.r` points reticulate at a dedicated venv at `~/.local/share/r-rdataretriever` pinned to Python 3.11 and `retriever` 2.4.0 (the compatibility patch in `R/library/data_retrieve.r` targets the 2.x API; `retriever` 3.x is not supported). Create it once with [uv](https://docs.astral.sh/uv/) (`brew install uv`):

```bash
uv venv --python 3.11 ~/.local/share/r-rdataretriever
uv pip install --python ~/.local/share/r-rdataretriever "retriever==2.4.0" "setuptools<70"
```

`retriever` 2.4.0 fails on import with `packaging.version.InvalidVersion: Invalid version: ''` when any cached dataset script has an empty minimum-version field. Fix it by adding an `and mod_ver` guard in the venv's `retriever/lib/scripts.py`:

```bash
sed -i '' 's/if hasattr(module, "retriever_minimum_version"):/if hasattr(module, "retriever_minimum_version") and mod_ver:/' \
  ~/.local/share/r-rdataretriever/lib/python3.11/site-packages/retriever/lib/scripts.py
```

A message such as `tidycensus is supported by Retriever version 3.0.1-dev` on load is harmless; it only means that one dataset script is skipped.

### Reproduce the database

To regenerate all per-source `.Rdata` files and recompile the database from scratch, set `recompile = TRUE` at the top of `R/RunMe.r` before running it; the download flags `DataRetrieve`, `DataVertNet` and `DataFishbase` control the four live-download frames. Google Sheet access requires authentication via `googlesheets4` on first use.  Contact mark.novak@oregonstate.edu to contribute new sources or curated values.

The run stops before any cached frame is loaded (step 2) when:

- **a parse script fails** (`recompile = TRUE`) -- every failure is printed as an `ERROR:` line and all of them are listed in the stop message, so one run reports them all. Fix the scripts and rerun with `recompile = TRUE`.
- **a cached frame was not rewritten** (`recompile = TRUE`) -- a frame in `sources/Rdata/` is older than the loop, e.g. an orphan left by a renamed or removed source, or a script that ran without saving. Delete the orphan or fix the script.
- **an expected frame is missing** (whatever `recompile` is) -- `R/library/check_cache.r` expects `BodyMass_<Source>.Rdata` for every `sources/databases/<Source>/BodyMass_<Source>.r` plus the four download frames, and the stop message names the flag to set for each missing frame (`recompile`, `DataRetrieve`, `DataVertNet` or `DataFishbase`). Frames that no current script writes only raise a warning. The three scripts whose `save()` target differs from their folder name are listed in `frame_overrides` in `check_cache.r`; a new source whose script saves under another name must be added there, otherwise the check stops and says so.

These guards are exercised on a throwaway source tree, without network access, by

```bash
Rscript R/library/tests/test_recompile_guard.R
```

### Use the compiled output

`TaxonBodyMass.csv` and `TaxonBodyMass_GenusLevel.csv` are tracked at the repository root and can be used directly without running the pipeline.

## Reproducibility note

Step 3 of the pipeline reads a lab-internal Google Sheet for curated mass overrides and citation mapping. External users who wish to fully reproduce the database will need to either (a) disable the Google Sheet step by removing or skipping that block in `R/RunMe.r`, which will omit lab-curated values, or (b) contact mark.novak@oregonstate.edu for the sheet structure. The compiled output CSVs committed to this repository reflect the full pipeline including the Google Sheet override.
