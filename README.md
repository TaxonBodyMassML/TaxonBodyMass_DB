# TaxonBodyMass_DB

A compiled, harmonized database of species body masses (in grams) drawn from many published sources spanning the full diversity of heterotrophic life — from microbes to large vertebrates. Developed in support of [FracFeed_DB](https://github.com/marknovak/FracFeed_DB) and [TaxonBodyMassML](https://github.com/TaxonBodyMassML/TaxonBodyMassML).

## Data Sources

Body mass data are compiled from primary sources and databases covering organisms across all major taxonomic groups, including bacteria, protists, marine zooplankton and invertebrates, spiders, fish, amphibians, reptiles, birds, and mammals (modern and fossil). Sources include both ecological databases (food-web, metabolic-scaling, predator-prey, movement) and taxonomic trait databases (life-history, body size). Live downloads from [FishBase](https://www.fishbase.org) and [SeaLifeBase](https://www.sealifebase.ca) are supported via the `rfishbase` package.

Bibliographic information for all sources is in `Bib/TaxonBodyMass_Citations.bib`.

## Pipeline

The pipeline is written in R. The main entry point is `R/RunMe.r`, which orchestrates all steps:

1. **Per-source parsing** — each source has its own script at `sources/databases/<SourceName>/BodyMass_<SourceName>.r` that reads raw data files, extracts taxon names and body masses, converts units to grams, and saves a cached `.Rdata` file to `sources/Rdata/`. Sources that report dry, ash-free dry or carbon mass are converted to wet grams with the group-specific factors in `R/library/mass_conversion.r` (`ToWetMass()`); each such script's `README.md` states the mass type reported by the source and the conversion group applied, and the CiteIDs of the conversion references are appended to the record's `source_mass` label (e.g. `Kendall_etal_2019; Studier_1992`) so they are cited alongside the source. Rows that the source itself flags as imputed, genus-averaged or taken from another species are removed in the parse scripts (`DropImputed()` in `R/library/helpers.r`) and logged to `audit/imputed_rows.csv` together with the records the raw-name rules of step 2 drop (life stages and small size classes) and the entries of the live download frames, which the download scripts save in `audit/imputed_rows_live.csv` (issue #40; the file is written after step 2, only when the parse scripts ran, and is the same whatever the download flags were); each source's `README.md` records this in an `Imputed rows:` line, which `R/library/check_source_docs.r` checks at every run. These cached files are git-ignored and regenerated by setting `recompile = TRUE` in `RunMe.r`.

2. **Taxon name cleaning** — applied uniformly to every source before merging. The rule of the database is that a cleaned name has two parts, `Genus_species`, or one, `Genus`, and nothing but letters; every raw name that does not already look so is reduced to that form by an explicit rule, and a raw name no rule covers stops the run (issue #38):
   - `R/library/fix_formatting.r` — `FixFormatting()` first normalizes encoding (only strings that are not valid UTF-8 are converted from Latin-1; diacritics are then transliterated to ASCII, so `Nausithoë rubra` becomes `Nausithoe_rubra`) and strips the sex signs ♀/♂, keeping the record as the species' value (the two `Tetrao urogallus ♀` records of Makarieva_2008 are `Tetrao_urogallus` records; issue #37). It then parses the name into its bracket groups and tokens and applies the tracked vocabulary `audit/raw_name_patterns.csv` (one regex per row with its `scope`, `class`, `action`, `note` and date; see `audit/README.md`): a capitalised word in brackets between genus and epithet is a **subgenus** and is removed (`Jaera (Jaera) albifrons` -> `Jaera_albifrons`; a genus written twice, `Castor Castor canadensis`, loses the repeat); **sex** marks (`(F)`, `Female`, `males`, the signs) and **form, strain, region** (`(colonial)`, `UAB CTIP`, `Bulgaria`) annotations are stripped and the record kept (the form written in place of the epithet, Brose_2005's `Conochilus_colonial`, folds to the genus-level record `Conochilus`; issue #48); of the Brose soil-web **size classes** the medium and large ones (`{m}`, `{l}`, `{xl}`, `{xxl}`, `{xxxl}`, `large`) are stripped and the record kept while the small ones (`{xs}`, `{s}`, `small`) are non-adult records and are dropped through `DropImputed()` (owner decision 2026-10-04); a **species group** marker (`Polypedilum halterale group`, `Hylaeus modestus grp`) is stripped and the record credited to the nominal species; a **synonym** or common name in brackets after the binomial and an **authority** (`L.`, `(Gmelin, 1789)`) are stripped; a lowercase third token, with or without a rank marker (`var.`, `ssp.`), is a subspecies or variety epithet and folds into the species (**trinomial**: `Acanthiza pusilla apicalis` -> `Acanthiza_pusilla`); a **placeholder** epithet (`sp.`, `spp.`, `spec.`, `indet.`, `ssp`, `undefinable`, `undetermined`, morphospecies codes such as `sp2` or `lassp8`, `species A`, `Unidentified`) or an identification **qualifier** (`cf.`, `aff.`, `nr.`) leaves the function as the marker `Genus_sp` / `Genus_cf` (or the word as written: `Genus_spp`, `Genus_spec`, `Genus_indet`, `Genus_nr`), which `fix_nontaxa.r` removes, as before; **life-stage** annotations (`(N1)`, `(IV)`, `(megalops)`, `Juveniles`, `immature`) make the record a non-adult and it is dropped through `DropImputed()` (scope rule of issue #8); **hybrids** (`Anas platyrhynchos x rubripes` -> `Anas_platyrhynchos`) and names listing two or more **ambiguous** alternatives (`Empidonax traillii/alnorum` -> `Empidonax_traillii`, `Pipilo maculatus, ocai` -> `Pipilo_maculatus`) are cut at the separator and credited to the first name written, a bare genus before the separator giving a genus-level record (owner decision 2026-10-04); the word `hybrid` in place of the epithet (`Anas hybrid`, VertNet) is a hybrid of unrecorded parentage and is credited to the bare genus the same way (issue #48; until then GBIF matched `Anas_hybrid` to *Chloephaga hybrida*); characters that cannot occur in a Latin name (**symbols**) are removed. Whitespace and capitalization are normalized throughout. Every name a rule touched is listed by class and source in `reports/warnings_raw_names.md`; a bracket group or trailing token no rule covers is an **error**: the name keeps its brackets and `CheckRawNames()` (below) stops the run, so a new pattern is classified by hand instead of being folded into a plausible binomial (which is how `Crithidia (Strigomonas) oncopelti` became the unresolvable `Crithidia_strigomonas`). Exercised without network access by `Rscript R/library/tests/test_raw_name_rules.R` (one fixture per class, the report, the format of the rename tables, 60 pinned ordinary names) and `Rscript R/library/tests/test_fix_formatting_encoding.R`
   - `R/library/fix_misspellings.r` — corrects known misspellings
   - `R/library/fix_nontaxa.r` — removes placeholder identifiers (the `Genus_sp`, `_spp`, `_spec`, `_indet`, `_type`, `_cf`, `_aff`, `_nr`, `_unk` markers, COMBINE's `Not_recognised` and the `_fragment(s)` / `_immature(s)` group labels of Hrycik_2024), functional-group labels and common names that the food-web compilations use as names (`Bacteria`, `Ciliates`, `Plankton`, the Chichewa fish names of the Lake Malawi web, ...; a one-token label would otherwise be filed as a genus-level record, issue #44), and other non-taxon entries. Exercised without network access by `Rscript R/library/tests/test_nontaxa_labels.R`
   - `R/library/filter_extinct.r` — removes extinct species (list in `audit/extinct_taxa.csv`, compiled by hand with `R/library/build_extinct_taxa.r` (not sourced by `RunMe.r`) from the status columns of MOM v10.2, PHYLACINE 1.2 and AVONET); the MOM and PHYLACINE scripts also drop their own extinct rows
   - `R/library/check_taxon_names.r` — three guards. `CheckRawNames()` runs right after `FixFormatting()` and stops the run with the list of raw names (and their sources and row counts) that carried brackets or trailing tokens the vocabulary does not cover (issue #38). `CheckTaxonNames()` runs after the chain and stops the run if any cleaned name is not `Genus_species` or `Genus` (whitespace, brackets, digits, a third token), which only a malformed replacement value in a rename table can produce; `RunMe.r` tells species-level from genus-level records by the underscore when it merges the sources, so such a name would be filed as a genus (issue #28). A unit test asserts that every key and value of `fix_misspellings.r` and every entry of `fix_nontaxa.r` has that format and that no key is duplicated (the `fix_taxonomy_ranks.r` keys match the `species` column, `Genus epithet` with a space, and are checked as such). `CheckSheetTaxa()` runs in step 3 on the rows of the lab Sheet, which are bound after the chain and so pass neither `FixFormatting()` nor `CheckTaxonNames()`: every Sheet taxon with a mass must be `Genus_species` or `Genus`, since the override matches Sheet names against the cleaned source names by equality; a three-part name (a subspecies) folds to the species with a warning, as the source trinomials do, and a cell with brackets, blanks, a digit, a lowercase genus or no name stops the run with the offending rows (taxon, mass, source) and a request to correct the Sheet (issue #48). Exercised without network access by `Rscript R/library/tests/test_taxon_name_guard.R` and `test_raw_name_rules.R`

3. **Google Sheet override** — lab-curated values (`BM_data` tab) take priority over the compiled sources. The Sheet rows with a mass are first checked by `CheckSheetTaxa()` (`R/library/check_taxon_names.r`; section 4 of `RunMe.r`): every taxon must be a cleaned name, `Genus_species` or `Genus`, a three-part name folds to the species with a warning, and anything else stops the run with the offending rows (issue #48). The rows are then split by the rule that tells the two kinds of record apart throughout the pipeline, the underscore (`R/library/sheet_override.r`, issue #57): a species-level row (`Genus_species`) replaces all compiled records of that species, so the Sheet value is the species' only record; a genus-level row (a bare `Genus`) is a genus-only record: it replaces the sources' genus-only rows written as that bare name (matched, like the species rows, by equality of the cleaned name) and joins the genus-only path of step 6, where it is resolved at genus rank, filtered, combined per genus and source and de-duplicated like the sources' rows. A genus-level Sheet row does not touch the species-level values of the genus (`Lepidostoma` replaces the sources' `Lepidostoma` rows and leaves `Lepidostoma_hirtum` alone; the genus mean of step 6 averages both). Until #57 every Sheet row entered the species path, where a bare name was dropped as unresolved or, for `Hypopomus`, resolved by ITIS to the species *Hypopomus artedi*; the rows such names left in the species enrichment cache are dropped when the cache is loaded (step 4). Exercised without network access by `Rscript R/library/tests/test_sheet_override.R`.

4. **Taxonomy enrichment and autotroph removal** — every unique name is resolved once to an accepted species and its full kingdom-to-species classification through GBIF, NCBI, WoRMS, Catalogue of Life (ChecklistBank), ITIS and Wikidata in turn, with a final GBIF backfill of missing higher ranks (`R/library/enrich_taxonomy.r`; details in `sources/passes/enrichment_pipeline.md`). Results are cached in `sources/enrich_cache.Rdata` (object `enrich_cache`; the genus-rank resolutions of step 6 are cached in the same file as `genus_cache`) so re-runs only query new names; the cache holds species-level names only, and a bare name an earlier run left there (step 3, issue #57) is dropped when it is loaded. Manual corrections live in `R/library/fix_taxonomy_ranks.r`. `R/library/filter_autotrophs.r` then removes autotrophs: the kingdoms Plantae, Viridiplantae and Fungi; predominantly photosynthetic phyla (Ochrophyta, Bacillariophyta, Haptophyta, Cryptophyta, Chlorophyta, Rhodophyta, Charophyta, Glaucophyta, Streptophyta, Euglenophyta, Cyanobacteria, Cyanobacteriota); and a curated list of photosynthetic or mixotrophic dinoflagellate and euglenid genera. Heterotrophic protists (ciliates, foraminifera, apicomplexans, kinetoplastids, amoebae, heterotrophic dinoflagellates and euglenids) are retained.

5. **Merging, de-duplication and range filter** — within each source, body masses are summarised as the geometric mean across records resolving to the same accepted species. Records are grouped by the source *label* (the first token of `source_mass`; the conversion CiteIDs appended after `;` do not split a source), and the six VertNet dumps are pooled as one source because the `traits` dump re-exports specimens of the class dumps (every dump label stays in `source_mass`). Before this first pass the records are put in a fixed order (input name, source label, `source_mass`, value; byte order, `OrderForPass1()` in `R/library/helpers.r`): `merge()` leaves the records of a name in the order of the bound source frames, and the floating-point sum behind a geometric mean depends on that order, so without it the last digit of a few `log10_range` values moved whenever a source or a cleaning rule reordered rows (issue #53). Exercised without network access by `Rscript R/library/tests/test_output_stability.R`.

   The same datum often reaches the database through several compilations (AVONET and EltonTraits both reproduce Dunning's CRC Handbook; COMBINE reproduces Amniote, PHYLACINE and MOM; Hoehler et al. 2023 reproduces Makarieva et al. 2008, which reproduces Chown et al. 2007; Meiri 2018 applies the Feldman et al. 2016 equations to the same lengths, and so on). Averaging such copies as independent estimates inflates `n` and biases the cross-source mean, so `R/library/dedupe_sources.r` collapses them before Pass 2 (issue #5). Two layers combine: the hand-maintained dependency registry `Bib/source_dependencies.csv` (one row per edge `child_label -> parent_label`, see below) collapses a child value into its parent, or into a sibling that shares a parent outside the database, only when the two values also agree within the edge's tolerance (`tol_log10`: 1e-6 for verbatim copies, 0.0105 where the child re-rounded or re-derived the value); edges are transitive, and `provenance_only` edges document a relation whose values generally differ: they grant no tolerance-based (registry) collapse. A blind rule then collapses values that are the same number to at least three significant digits in any two sources of a species, whatever the registry says about the pair (identical values are the same datum; on a `provenance_only` pair such a collapse is labelled `blind (provenance_only edge)` in the summary report); values of one or two significant digits, round numbers such as 20 or 1500 g, are left alone as ambiguous. Matching values form a component per species; the registry ancestor (or the lowest-`priority` sibling) is kept and the others are recorded in `source_dependencies` as `dropped<kept`. `reports/dedupe_summary.md` lists every edge with the species it shares and collapsed, the species left with a single independent value, and the residual identical pairs the registry does not explain (candidates for new edges or shared primary literature).

   Across sources, the independent values are combined as the arithmetic mean (owner decision 2026-10-03, issue #16): the arithmetic mean is the published convention of the database, so outputs stay comparable with earlier releases and with the manuscript; within-source skew is already handled by the geometric mean of the first pass, and the cross-source step combines per-source central values, where the choice matters less once duplicated values are collapsed; switching to the geometric mean would have moved 795 species by more than 0.1 log10, always downward, a larger and systematic shift than de-duplication, and would entangle two effects that should stay separable; neither choice affects `log10_range` or the range filter. `log10_range` records the spread of the independent values (log10 of the largest over the smallest, written to six decimals; the range filter below and the QC reports use the unrounded value), `source_mass` lists every contributing source, `n` counts every record, and `n_sources`, `n_independent` and `source_dependencies` record the de-duplication. `R/library/check_enriched.r` writes QC reports to `reports/` (`warnings_taxonomy.md`, which also lists every cleaned name no enrichment stage resolved, species-level names and genus-only names (step 6) alike, with its sources and row counts; `warnings_mass_values.md`; `warnings_name_change.md`), and species whose independent values disagree by more than one order of magnitude (`log10_range > 1`) are removed (`R/library/remove_high_range.r`). Counts from this step (including `nValuesCollapsed`, `nSpeciesSingleDatum` and `nDependencyEdges`) are written to `../TaxonBodyMassML/ms/numbers_db.tex` for the manuscript.

6. **Genus-level aggregation** — `TaxonBodyMass_GenusLevel.csv` gives, for every accepted genus, the arithmetic mean of the cross-source means of its species (step 5) and of its genus-only record, each with the weight of one value; synonymous or misspelt input genera therefore fold into the accepted name. A genus-only record is a value for an organism identified to genus only, measured or compiled as the source reports it (population means included, issue #29): a name written as a bare genus (placeholder names such as `Genus sp.` or `Genus spec.` are dropped instead, issue #43), including the genus-level rows of the lab Sheet, which replace the sources' rows of the same bare name and leave the species-level values of the genus alone (step 3, issue #57). Such records get the machinery of the species path (`R/library/enrich_genus.r`, issue #49). Every bare name is resolved once at genus rank, through the accepted genera of the enrichment cache and the GBIF backbone exact-name lookup, with the class/order/family hints the source gives (VertNet, Castro_2025, Pata_2025, Makarieva_2008): synonyms and misspellings fold into the accepted genus (`Dendroica` -> `Setophaga`, `Clethrionomys` -> `Myodes`), homonyms are settled by the hints or, failing those, by preferring the heterotroph kingdoms (GBIF's name matcher files `Coleoptera` and `Oligochaeta` as plant genera), and names of ranks above genus leave the table: the backbone's own family, order and class usages (`Staphylinidae`, `Araneae`, `Oligochaeta`), the majority reading of the other GBIF checklists for names the backbone lacks or misfiles (`Crustacea`, `Heteroptera`, `Tanytarsini`, `Polychaeta`), a two-name curated list (`Anisoptera`, `Hydracarina`) and the family-group suffixes; fuzzy matches are accepted only for names of six letters or more with no exact usage at any rank, at confidence 80 or more and at most two letters apart. The answers are cached as `genus_cache` in `sources/enrich_cache.Rdata`; names no stage resolved are listed in `reports/warnings_taxonomy.md` with their sources and rows, and their rows are dropped. The resolved records are filtered with `FilterAutotrophs()` (the extinct list is species-level and does not apply), combined as one value per genus and source (geometric mean, VertNet dumps pooled), de-duplicated with the registry of step 5 (`Brose_etal_2018` -> `Brose_2005`, -> `Hechinger_etal_2011`), and combined as the arithmetic mean of the independent per-source values: that single record enters the genus mean with the weight of one species, and `n_independent` counts the species' independent values plus one per independent source of genus-only records (owner decision 2026-10-04; one record per source instead would have moved 48 genera by at most 0.17 log10). Names of ranks above genus are dropped without a separate output (167 names and 9,249 rows at the 2026-10-04 run; owner decision), and genus-only records are not range-checked against the genus's species values (issue #34). `reports/genus_only_records.md` lists, at every run, the names resolved above genus, the autotroph genera removed, the fuzzy matches and homonym choices to check by eye, the synonyms folded, the values collapsed as copies, and the genus-only records more than an order of magnitude from the genus's species values. Exercised without network access by `Rscript R/library/tests/test_genus_only_records.R`.

7. **Citations and provenance** (issue #1) — `R/RunMe.r` section 8 reads both bibliographies, the hand-curated `Bib/TaxonBodyMass_Citations.bib` (BibDesk) and the generated `Bib/TaxonBodyMass_PrimaryCitations.bib` (built by `R/library/citations/run_citations.r --bib` from Crossref metadata or owner-approved fields, never edited by hand; a key present in both files stops the run), and both citation tabs of the lab Sheet, `BM_citations` (source labels and conversion references -> bib keys) and `BM_primary_citations` (the verified primary references, appended by `run_citations.r --sheet`; read from the Sheet when the tab exists, else from the tracked snapshot `Bib/BM_primary_citations_snapshot.csv`). Sheet rows whose key is in neither bib are listed in `reports/warnings_citations.md` instead of being dropped silently. `Bib/TaxonBodyMass_CitationCiteIDs.csv` keeps `Bibcite, CiteID` as its first two columns and gains `doi`, `role` and `bib_file`. Every record's `source_mass` is split before step 5 into the source label and the conversion CiteIDs appended by `LabelWithConversion()`, the parse scripts' per-record reference keys (`ref_keys`) travel through the first averaging pass, and `TaxonBodyMass_Provenance.csv.gz` links every species of `TaxonBodyMass.csv` to its source labels and, where a source's reference list has been ingested and verified (`sources/databases/<Src>/primary_references.csv`), to the study that measured the animal, with the hop and provenance type of each reference; records without a reference get the default of the registry `Bib/source_provenance_classes.csv`. The checks (every primary bib key in a bib file, every primary CiteID in a Sheet tab, every accepted reference with a DOI or an approval, per-source coverage) are written to `reports/warnings_citations.md`. The tooling, its decision rules and its hallucination-robustness rules are described in `R/library/citations/README.md`; `RunMe.r` sources only its offline part and never calls Crossref, OpenAlex or Scite.

### Source dependency registry

`Bib/source_dependencies.csv` records which sources copy or derive their body masses from which others. (The *provenance* registry `Bib/source_provenance_classes.csv`, which classifies every source for the primary-source attribution of issue #1, is described in `R/library/citations/README.md`.) Columns: `child_label` (a `source_mass` label), `parent_label` (a label, or the name of a compilation outside the database such as `Dunning_2008`, `White_2006`, `Nagy_1999`, `CareyJudge_2000`), `parent_in_db` (TRUE/FALSE), `relation` (`copies`, `via` an intermediate compilation, `shared_primary`, `derived_same_input`, or `provenance_only`), `tol_log10` (the largest |log10 difference| at which a child value counts as the parent's), `priority` (which of several siblings of an external parent is kept: the lowest number; one value per label), `status` (`confirmed` by the source's own documentation or `suspected` from the values alone), `n_rows_child` (records the child attributes to the parent where it does so per row), `evidence` and `added`. Where several routes connect two labels the loosest tolerance applies. `LoadSourceDependencies()` stops the pipeline when a child or an in-database parent is not a label of any source frame, when an external parent is one, on a cycle, or on conflicting priorities, so a renamed or removed source has to be reflected in the registry. Add an edge when a source's documentation or a high fraction of identical values (see the residual table of `reports/dedupe_summary.md`) shows that it reproduces another; use `provenance_only` when the values differ (the pair then gets no tolerance, but values identical to three significant digits are still collapsed by the blind rule and counted per edge in the report). The helper is tested without network access by

```bash
Rscript R/library/tests/test_dedupe_sources.R
```

and `Rscript R/library/dedupe_audit.r [--before <earlier TaxonBodyMass.csv>]` replicates Pass 1, the de-duplication and Pass 2 from `sources/Rdata` and checks the released CSV against it (invariants, agreement, per-edge fractions, the shifts the de-duplication causes).

| `TaxonBodyMass_Provenance.csv.gz` | One row per species x source label x reference for the species of `TaxonBodyMass.csv` (pipeline step 7, issue #1): `genus`, `species`, `taxon`, `source_mass` (one label), `source_bibcite`, `origin` (`pipeline` or `BM_data`), `hop` (0: the source measured the animal or a conversion factor; 1: the source cites the reference; 2: through an intermediate compilation), `via_cite_id`, `ref_role` (`measurement`, `compilation`, `equation`, `conversion`, `self`), `provenance_type` (`measured_in_source`, `compiled_from`, `compiled_via_compilation`, `compilation_terminal`, `derived_allometry`, `derived_imputed`, `database_record`, `conversion_factor`, `unknown`), `primary_cite_id`, `primary_bibcite`, `primary_doi`, `match_status` (the verification status of the reference; `unmatched_key` for a key the source's reference list lacks, `uningested` for a source whose reference list has not been ingested yet), `n_records` (records behind the row). Gzipped CSV, deterministic (no timestamp); rows in a fixed order |
| `reports/warnings_citations.md` | The checks of pipeline step 7: totals, problems (bib keys, CiteID rows, accepted references without DOI or bib entry), the Sheet rows whose Bibcite is in neither bib, the labels without a CiteID row, and the per-source coverage of the provenance table (record links resolved to a primary reference, reference counts by status); regenerated at every run |
| `Bib/TaxonBodyMass_CitationCiteIDs.csv` | Maps BibTeX keys to `source_mass` labels for citation tracing: `Bibcite`, `CiteID` (the first two columns, read by TaxonBodyMassML), `doi` (from the bib entry, when it has one), `role` (`source`, `conversion` or `primary`), `bib_file` (`Citations` or `PrimaryCitations`) |
| `Bib/TaxonBodyMass_Citations.bib` | Hand-curated BibTeX bibliography (BibDesk) of the sources, the conversion references and the lab Sheet's citations |
| `Bib/TaxonBodyMass_PrimaryCitations.bib` | Generated bibliography of the verified primary references (`run_citations.r --bib`; `%% GENERATED`, never edited by hand, re-derivable from the `primary_references.csv` files and the response cache) |
| `Bib/BM_primary_citations_snapshot.csv`, `Bib/BM_citations_snapshot.csv` | The two citation tabs of the lab Sheet as last read by `run_citations.r --sheet` (the offline fallback of pipeline step 7 and the record of every append) |

The tables are reproducible byte for byte: for a given cache (`sources/Rdata`, `sources/enrich_cache.Rdata`) and state of the lab Sheet, two runs write identical `TaxonBodyMass.csv`, `TaxonBodyMass_GenusLevel.csv`, `TaxonBodyMass_Provenance.csv.gz`, `audit/imputed_rows.csv` and `Bib/TaxonBodyMass_CitationCiteIDs.csv`, because the records are put in a fixed order before the first averaging pass and the derived floating-point columns are rounded at write time (`log10_range` to six decimals, `mass_g` to four significant figures; issue #53). The reports under `reports/` differ between runs only in their timestamp line.

## Usage

### Prerequisites

Install the required R packages:

```r
install.packages(c("plyr", "dplyr", "googlesheets4", "stringr", "readxl"))
install.packages("rfishbase")
install.packages("rdataretriever")
```

The `rdataretriever` package requires Python and the [`retriever`](https://retriever.readthedocs.io) Python package. It is used only when `DataRetrieve = TRUE` in `RunMe.r`. `RunMe.r` points reticulate at a dedicated venv at `~/.local/share/r-rdataretriever` pinned to Python 3.11 and `retriever` 2.4.0 (the compatibility patch in `R/library/data_retrieve.r` targets the 2.x API; `retriever` 3.x is not supported). Create it once with [uv](https://docs.astral.sh/uv/) (`brew install uv`):

```bash
uv venv --python 3.11 ~/.local/share/r-rdataretriever
uv pip install --python ~/.local/share/r-rdataretriever "retriever==2.4.0" "setuptools<70"
```

`retriever` 2.4.0 fails on import with `packaging.version.InvalidVersion: Invalid version: ''` when any cached dataset script has an empty minimum-version field. Fix it by adding an `and mod_ver` guard in the venv's `retriever/lib/scripts.py`:

```bash
sed -i '' 's/if hasattr(module, "retriever_minimum_version"):/if hasattr(module, "retriever_minimum_version") and mod_ver:/' \
  ~/.local/share/r-rdataretriever/lib/python3.11/site-packages/retriever/lib/scripts.py
```

A message such as `tidycensus is supported by Retriever version 3.0.1-dev` on load is harmless; it only means that one dataset script is skipped.

### Reproduce the database

To regenerate all per-source `.Rdata` files and recompile the database from scratch, set `recompile = TRUE` at the top of `R/RunMe.r` before running it; the download flags `DataRetrieve`, `DataVertNet` and `DataFishbase` control the four live-download frames. Google Sheet access requires authentication via `googlesheets4` on first use.  Contact mark.novak@oregonstate.edu to contribute new sources or curated values.

The run stops before any cached frame is loaded (step 2) when:

- **a parse script fails** (`recompile = TRUE`) -- every failure is printed as an `ERROR:` line and all of them are listed in the stop message, so one run reports them all. Fix the scripts and rerun with `recompile = TRUE`.
- **a cached frame was not rewritten** (`recompile = TRUE`) -- a frame in `sources/Rdata/` is older than the loop, e.g. an orphan left by a renamed or removed source, or a script that ran without saving. Delete the orphan or fix the script.
- **an expected frame is missing** (whatever `recompile` is) -- `R/library/check_cache.r` expects `BodyMass_<Source>.Rdata` for every `sources/databases/<Source>/BodyMass_<Source>.r` plus the four download frames, and the stop message names the flag to set for each missing frame (`recompile`, `DataRetrieve`, `DataVertNet` or `DataFishbase`). Frames that no current script writes only raise a warning. The three scripts whose `save()` target differs from their folder name are listed in `frame_overrides` in `check_cache.r`; a new source whose script saves under another name must be added there, otherwise the check stops and says so.

These guards are exercised on a throwaway source tree, without network access, by

```bash
Rscript R/library/tests/test_recompile_guard.R
```

After the completeness check, `CheckImputedLive()` (`R/library/check_cache.r`) warns, without stopping, when a live frame in `sources/Rdata/` is not the file whose download saved its rows in `audit/imputed_rows_live.csv` (the frame was downloaded again without saving its entries, or the cache was copied from a run with a different frame); rerun with that frame's flag set to TRUE to refresh the frame and its entries together (issue #40). The merge of the saved entries into `audit/imputed_rows.csv` and this check are exercised by

```bash
Rscript R/library/tests/test_imputed_live.R
```

### Use the compiled output

`TaxonBodyMass.csv` and `TaxonBodyMass_GenusLevel.csv` are tracked at the repository root and can be used directly without running the pipeline.

## Reproducibility note

Step 3 of the pipeline reads a lab-internal Google Sheet for curated mass overrides and citation mapping. External users who wish to fully reproduce the database will need to either (a) disable the Google Sheet step by removing or skipping that block in `R/RunMe.r`, which will omit lab-curated values, or (b) contact mark.novak@oregonstate.edu for the sheet structure. The compiled output CSVs committed to this repository reflect the full pipeline including the Google Sheet override.
